# ⬆️ Migrating to 2.0.0

ItemIO 2.0.0 is focused on performance : most operations are 2 to 50 times faster than in 1.8.1
(see [Performance](#performance)). This page lists every change that can affect a datapack using ItemIO.

---

## Breaking changes

### Config location : `data.itemio`

The config of a container is now read from the `data` field of the entity, for every entity type :
`data.itemio.ioconfig` and `data.itemio.nbt_items_path`.

The previous locations (the item of item frames, armor stands and item displays) still work as a fallback,
when `data.itemio.ioconfig` doesn't exist. When both exist, `data.itemio` is used.
The same applies to servos : `data.itemio.ioconfig.{filters, items}`, with a fallback on
`Item.components."minecraft:custom_data".itemio.ioconfig`.

```diff
- data modify entity @s item.components."minecraft:custom_data".itemio.ioconfig set value [...]
+ data modify entity @s data.itemio.ioconfig set value [...]
```

### `ioconfig_from_storage` is removed

The tag `itemio.container.ioconfig_from_storage` and the field `itemio.ioconfig_from_storage` are removed.
Write the ioconfig in `data.itemio.ioconfig` of the container entity instead
(it can be copied from your storage when it changes).

### Auto handled IO : new API

The containers with the tag `itemio.container.auto_handled_io` use a new, simpler API, with only the
`itemio.io` scores and the `itemio:io` storage (see [Auto handled IO](https://edayot.github.io/ItemIO/containers/index.html#auto-handled-io)).

| 1.8.1 | 2.0.0 |
| --- | --- |
| `storage itemio:io Item_auto_output` | `storage itemio:io offer` |
| `function #itemio:calls/auto_handled_output` | `function #itemio:calls/offer` |
| `score #remove_count itemio.math.output` | `score #count_to_remove itemio.io` |
| input : set `#success_input`, `#count_to_remove` and `itemio:io output` | input : set `#count_to_remove itemio.io` only |
| `function #itemio:calls/disable_servo` when nothing is accepted (with `#servos_transfer itemio.math`) | done by ItemIO |

`#itemio:calls/auto_handled_output` is removed. Example with SimpleDrawer :

```diff
  # simpledrawer:impl/new_drawer/itemio/auto_handled_input
  execute if score #success simpledrawer.io matches 1 run scoreboard players operation #count_to_remove itemio.io = #count_insert simpledrawer.io
- execute if score #success simpledrawer.io matches 1 run scoreboard players set #success_input itemio.io 0
- execute if score #success simpledrawer.io matches 1 run scoreboard players set #success_input itemio.io 1
- execute if score #success simpledrawer.io matches 1 run data modify storage itemio:io output set from storage simpledrawer:io output
- execute if score #success simpledrawer.io matches 0 if score #servos_transfer itemio.math matches 1 run function #itemio:calls/disable_servo
```

```diff
  # simpledrawer:impl/new_drawer/itemio/auto_handled_output_loop
- data modify storage itemio:io Item_auto_output set from storage simpledrawer:main temp.Items_aho[0].item
- execute store result storage itemio:io Item_auto_output.count int 1 run scoreboard players get #count_aho simpledrawer.math
- function #itemio:calls/auto_handled_output
- scoreboard players operation #count simpledrawer.io = #remove_count itemio.math.output
+ data modify storage itemio:io offer set from storage simpledrawer:main temp.Items_aho[0].item
+ execute store result storage itemio:io offer.count int 1 run scoreboard players get #count_aho simpledrawer.math
+ function #itemio:calls/offer
+ scoreboard players operation #count simpledrawer.io = #count_to_remove itemio.io
```

The context of the output call (`itemio:io filters`, `itemio:io input`) is restored after each offer.

### `itemio.container.nope` and `itemio.container.auto_handled_io` don't use the vanilla block

In 1.8.1, the vanilla container under these entities was also used for inputs and outputs
(e.g. a `nope` custom block on a barrel still accepted items in the barrel).
Now a `nope` container accepts and gives nothing, and an auto handled container only uses its function tags.

### The yellow shulker box loot table is no longer overridden

ItemIO 1.8.1 inserted items in vanilla containers through a yellow shulker box and a barrel placed in the
forceloaded chunk, and overrode `minecraft:blocks/yellow_shulker_box` (a yellow shulker box mined with a tool
with `custom_data={drop_contents:1b}` dropped its contents). The override is removed, and the two blocks are
removed on load.

### `itemio.container.hopper_protection_{offset}` tags

They are read when the container is initialised (`#itemio:calls/container/init`), add them before.
Containers initialised before 2.0.0 are updated on their first tick.

### Transfers

- The destination markers are searched once per `#itemio:calls/transfer` call. When a destination refuses the item,
  the next one is the next nearest to the origin (in 1.8.1 : the nearest to the destination that refused it).
- The input side of a destination marker is read from `data.itemio.input_side` (as documented),
  or `data.itemio.ioconfig.input_side`. Without input side, the destination has no side
  (in 1.8.1, the input side of the previous call was used).
- The `items` of a destination are compared with the item (in 1.8.1, with the `items` of the extract servo).
- The input count of a vanilla container must be between 1 and 99 (like any item stack).

### Servos

- The insert servos are sorted by their own distance to the source (in 1.8.1, by the distance of their block).
  This only changes the order of insert servos on the same block.
- An extract servo stops its retries (`itemio.servo.retry_limit`) at the first transfer that fails.
- `#max_network_per_tick itemio.math` set to 0 now means no limit (in 1.8.1, no network was processed),
  and `#max_servos_per_tick itemio.math` is now applied (it was never reached in 1.8.1).

### Vanilla containers

- When the right half of a double chest can only take a part of the input, the rest goes into the left half
  (in 1.8.1, the left half was only used when the right half took nothing).
- A hopper minecart that is no longer under a container is enabled again within 4 ticks.

### Internal state

The internal storages (`itemio:main`, `itemio:main.input`, `itemio:main.output`) and the scores of
`itemio.math`, `itemio.math.input` and `itemio.math.output` changed. They were never part of the API.
The servos no longer use the tag `itemio.servo.already` (score `itemio.servo.processed_tick` instead).


## Deprecations

- The filter `minecraft` (`{minecraft:{logs:1b}}`) tests every item tag of the game, use
  `{item_predicate:"#minecraft:logs"}` instead.


## New features

- `storage itemio:io destinations` : the destinations of `#itemio:calls/transfer`, without any marker
  (see [Transfer](https://edayot.github.io/ItemIO/function_calls/index.html)).
- `#itemio:calls/offer` : see [Auto handled IO](https://edayot.github.io/ItemIO/containers/index.html#auto-handled-io).
- `#itemio:calls/container/destroy` : to call as the container entity when it is destroyed
  (it was documented, but did not exist before 2.0.0).
- The `ctc` filter : an entry without `id` matches every item of its source (`{ctc:[{from:"airdox_:simpledrawer"}]}`).


## Bug fixes

- The output of a custom container succeeded without any item when its first slot was empty.
- The output of a double chest facing east or west never used its left half from its right half.
- The fuel slot of a brewing stand accepted any item from the sides.
- A shulker box was accepted in a shulker box.
- The `merge` filter never matched.
- The jukebox only accepted a music disc depending on a previous operation.
- The output of a `nbt_items` container removed `#max_output_count` items even when less were moved.
- The items marked as GUI (`itemio.gui`) were deleted from vanilla containers by an input.


## Performance

Measured with `/stopwatch` on Minecraft 26.3 (`uv run python bench/run.py`, see [Contributing](https://edayot.github.io/ItemIO/contributing.html)),
median time of one operation.

| Operation | 1.8.1 | 2.0.0 | Speedup |
| --- | ---: | ---: | ---: |
| Input of 1 item in a barrel | 89 µs | 23 µs | ×3.9 |
| Input in a barrel, only the last slot fits | 883 µs | 17-33 µs | ×27-53 |
| Transfer barrel → barrel | 171 µs | 78 µs | ×2.2 |
| Transfer barrel → barrel, 3000 other entities loaded | 780 µs | 134 µs | ×5.8 |
| Network process (retry limit 8) | 1550 µs | 750 µs | ×2.1 |
| Network process, nothing to move | 230 µs | 60 µs | ×3.8 |
| Hopper cycle of a custom container | 447 µs | 183 µs | ×2.4 |
| `id` filter | 24.5 µs | 10.5 µs | ×2.3 |
| Tick, 100 vanilla containers | 440 µs | 200 µs | ×2.2 |
| Tick, 100 custom containers | 210 µs | 120 µs | ×1.8 |
| Tick, no ItemIO entity, 3000 other entities | 205 µs | 105 µs | ×2.0 |
